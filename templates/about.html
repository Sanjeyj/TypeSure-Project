About the Project

About TypeSure

TypeSure is a Tamil-language spelling detection and correction tool. It processes Tamil Unicode text locally on a Flask server, compares each token against a curated dictionary, and suggests corrections using a combination of dictionary lookup and string-similarity algorithms. The system is designed to be transparent, explainable and privacy-respecting.

🎯 Objectives

  • Provide a simple, explainable Tamil spelling assistant.
  • Work entirely without paid APIs or external cloud services.
  • Demonstrate practical application of NLP algorithms for Indian languages.
  • Help students and general users type Tamil more confidently.
  • Maintain full transparency about algorithmic limitations.

⚙️ How TypeSure Works

1. Text Input & Preprocessing

When you submit Tamil text, TypeSure first applies Unicode NFC (Canonical Composition) normalization using Python's unicodedata module. This ensures that characters stored in different binary forms on different systems are treated identically. For example, a combining vowel sign followed by a consonant will be composed into the correct composite codepoint before comparison.

2. Tokenization

The normalized text is tokenized using regular expressions that respect Tamil Unicode ranges (U+0B80–U+0BFF). Punctuation, spaces, numbers, and English words are separated into distinct spans and preserved. Only Tamil-script tokens are passed to the spell-checking pipeline. Non-Tamil content is never modified.

3. Dictionary Membership Check

Each Tamil token is checked against an in-memory Python set containing the curated dictionary. Set membership testing is O(1) average case, making the check near-instantaneous. Words found in the dictionary are marked as "recognized". Words not found are flagged as "unknown" for further analysis.

4. Suggestion Generation

For each unknown word, TypeSure searches the dictionary for similar words using the Levenshtein edit-distance algorithm. A length pre-filter eliminates candidate words whose length differs by more than the threshold (2 edits), substantially reducing the search space before the more expensive dynamic programming computation runs.

5. Candidate Ranking

Candidates are ranked primarily by edit distance (lower is better), then alphabetically as a stable tiebreaker. Up to 5 suggestions are returned per unknown word. The user must explicitly accept or reject each suggestion — TypeSure never auto-corrects text.

📐 Algorithm Documentation

Unicode NFC Normalization

Tamil text on different systems may store the same character in different binary forms. NFC (Canonical Composition) ensures consistent representation before any comparison is made. This is critical because a visually identical Tamil word could fail a byte-level comparison if one copy uses composed codepoints and the other uses decomposed sequences.

Levenshtein Edit Distance

The edit distance between two strings is the minimum number of single-character edits (insertions, deletions, substitutions) needed to transform one string into the other. TypeSure uses the Wagner–Fischer dynamic-programming algorithm with a single-array optimization to keep memory usage at O(min(m, n)). The time complexity is O(m × n) where m and n are the lengths of the two strings.

For Tamil words (typically 3–8 characters), a threshold of 2 catches common single- and double-character typing errors without producing too many irrelevant suggestions. Common Tamil errors include missing pulli marks (virama), doubled consonant omissions, and vowel sign substitutions.

Example: வணககம் → distance 2 → வணக்கம் (missing க்க pulli)

Length Pre-Filter

Before computing Levenshtein distance, TypeSure applies a simple but effective optimization: only dictionary words whose length differs by at most the maximum distance threshold are considered. This eliminates the majority of candidates and dramatically reduces computation time for large dictionaries.

⚠️ Limitations

  • The starter dictionary contains a limited set of common Tamil words and does not cover the full Tamil lexicon (~100,000+ words).
  • The system does not understand Tamil grammar, morphology, or sentence context.
  • Correctly spelled but rare or technical Tamil words may be flagged as unknown.
  • Edit-distance suggestions may occasionally be irrelevant for very short words.
  • Tamil compound words and agglutinative forms may not all be present in the dictionary.
  • Dictionary coverage percentage reflects only the overlap between the input text and the dictionary — it is not a measure of spelling accuracy.

🔒 Privacy & Security

  • All text processing happens on the TypeSure server. No text is sent to any third-party API or cloud service.
  • By default, only aggregate statistics (word count, issue count, timestamp) are stored in the SQLite database.
  • Full text is saved in history only when you explicitly opt in using the "Save my full text" checkbox.
  • You can clear all history at any time using the "Clear History" function. This permanently deletes all stored records.
  • The dictionary import feature processes uploaded files server-side and retains only the individual words. The uploaded file itself is not stored.
  • Security headers (CSP, X-Frame-Options, X-Content-Type-Options) are applied to every response.
